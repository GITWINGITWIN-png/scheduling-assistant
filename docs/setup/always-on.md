# ให้เลขาทำงานตลอดบนเครื่องนี้ (systemd user service)

เลขา v2 รันเป็น **systemd user service** ชื่อ `my-secretary`:

- เปิดเองตอนบูตเครื่อง (เครื่องนี้เปิด linger ไว้แล้ว จึงไม่ต้องล็อกอินก่อน)
- ล้มแล้วเปิดใหม่เองใน 5 วินาที
- log เก็บใน journal ของระบบ

โปรเซสเดียวรันทุกส่วน: หน้าเว็บ (http://localhost:8000) นาฬิกาเลขา และบอท Discord

## ก่อนติดตั้ง: เรื่องที่ต้องรู้

- **ติดตั้งแล้ว service ของ v1 ถูกแทนที่** v1 ใช้ชื่อ service เดียวกัน (`my-secretary`) และรันอยู่ตอนนี้
  - `install.sh` เก็บไฟล์ service ของ v1 ไว้ที่ `~/.config/systemd/user/my-secretary.service.v1.bak` ก่อนเขียนทับ
  - **หลังติดตั้ง ฟีเจอร์ของ v1 จะหยุด** เช่น การอ่านอีเมล ของเหล่านี้กลับมาใน v2 ตั้งแต่ B2
  - ถ้าอยากให้ v1 ทำงานต่อไปก่อน ให้ทดสอบ v2 แบบรันเองที่พอร์ตอื่น (ดูหัวข้อสุดท้าย) แล้วค่อยติดตั้งทีหลัง
- **v2 เปิดให้เฉพาะเครื่องนี้เท่านั้น** (`127.0.0.1`)
  - v1 เปิดให้ทุกเครือข่าย (`0.0.0.0`) รวมทั้ง LAN
  - การเปิดจาก iPad ผ่าน Tailscale กลับมาใน B8 โดยรับเฉพาะเครื่องใน Tailscale ตามที่ตกลงไว้
  - ถ้าต้องการเปิดให้ทุกเครือข่ายเหมือน v1 ไปก่อน ให้ติดตั้งด้วย `HOST=0.0.0.0 ./deploy/install.sh` แต่ไม่แนะนำ เพราะใครก็ตามในเครือข่ายเดียวกันจะถามเลขาและใช้โควตา Claude ของคุณได้

## ติดตั้ง หรืออัปเดต

```bash
cd ~/Projects/my_secretary
./deploy/install.sh
```

สคริปต์ทำ 4 อย่าง และรันซ้ำได้ทุกครั้งหลัง `git pull`:

1. `uv sync --frozen` ติดตั้งแพ็กเกจ Python ตาม `backend/uv.lock`
2. `npm ci && npm run build` build หน้าเว็บ
3. เขียนไฟล์ service ไปที่ `~/.config/systemd/user/my-secretary.service`
4. `enable` (เปิดเองตอนบูต) และ `restart`

จากนั้นสคริปต์รอให้ `/api/health` ตอบ

## คำสั่งที่ใช้บ่อย

| อยากรู้ / อยากทำ | คำสั่ง |
|---|---|
| ทำงานอยู่ไหม | `systemctl --user status my-secretary` |
| ดู log สด (Ctrl+C เพื่อออก) | `journalctl --user -u my-secretary -f` |
| ดู log ย้อนหลัง 100 บรรทัด | `journalctl --user -u my-secretary -n 100` |
| ดู log ตั้งแต่บูตครั้งนี้ | `journalctl --user -u my-secretary -b` |
| รีสตาร์ท เช่น หลังแก้ `backend/.env` | `systemctl --user restart my-secretary` |
| หยุดชั่วคราว (บูตครั้งหน้าจะกลับมาเอง) | `systemctl --user stop my-secretary` |
| ปิดถาวร (บูตแล้วไม่เปิด) | `systemctl --user disable --now my-secretary` |
| เอาออกทั้งหมด (ข้อมูลไม่หาย) | `./deploy/uninstall.sh` |
| เช็กว่าเปิดตอนบูตโดยไม่ต้องล็อกอิน | `loginctl show-user $USER -p Linger` ต้องได้ `Linger=yes` (ถ้าไม่ใช่ ใช้ `loginctl enable-linger $USER`) |

**อ่าน status ยังไง:**

- `Active: active (running)` = ทำงานอยู่
- `activating (auto-restart)` = เพิ่งล้มและกำลังเปิดใหม่ ให้ดู log ว่าล้มเพราะอะไร

**รอบของช่วงใหม่เริ่มแบบปิดเสมอ** แม้ service จะรีสตาร์ทกลางช่วง ก็ไม่มีอะไรใหม่ทำงานเอง คุณเปิดเองในหน้าตั้งค่า (นาฬิกาเลขา) ตอนทดสอบช่วงนั้น ทุกการเปิดหรือปิดอยู่ในหน้าบันทึกและย้อนกลับได้ ส่วนสำรองฐานข้อมูลเปิดตั้งแต่ B1

รอบที่ทำแล้วมีอะไรเกิดขึ้นจะขึ้นในหน้า "สิ่งที่เลขาทำ" ส่วนรอบที่ไม่มีอะไรใหม่ (เช่นเฝ้าอีเมลแล้วไม่มีฉบับใหม่) ไม่ขึ้น เพื่อไม่ให้หน้านั้นรก เวลาที่ทำล่าสุดของทุกรอบยังดูได้ในหน้าตั้งค่า

## ข้อมูลอยู่ที่ไหน

| ไฟล์ | คืออะไร |
|---|---|
| `~/.secretary/secretary.db` | ที่เก็บกลางของ v2 (อยู่นอก repo จึงไม่มีทาง commit พลาด) |
| `~/.secretary/backups/secretary-YYYY-MM-DD.db` | ไฟล์สำรองรายวัน |
| `backend/.env` | token และค่าลับ (อยู่ใน .gitignore) |
| `backend/secretary.db` | ข้อมูลของ v1 v2 ไม่แตะไฟล์นี้ |

### กู้คืนจากไฟล์สำรอง

```bash
systemctl --user stop my-secretary
cd ~/.secretary
mkdir -p broken && mv secretary.db* broken/          # เก็บของเดิมไว้ก่อน ไม่ลบ
cp backups/secretary-2026-11-05.db secretary.db      # เลือกวันที่ต้องการ
systemctl --user start my-secretary
```

## ทดสอบ v2 โดยยังไม่แทนที่ v1

```bash
cd ~/Projects/my_secretary/backend
uv run uvicorn app.main:app --port 8001
```

จากนั้นเปิด http://localhost:8001 แล้วกด Ctrl+C เมื่อเสร็จ

ข้อควรรู้:

- รันพร้อม service ได้ แต่**นาฬิกาและบอท Discord ทำงานได้ทีละตัวเท่านั้น**
  - ตัวที่เปิดก่อนจะจองไฟล์ `~/.secretary/worker.lock`
  - ตัวที่เปิดทีหลังเปิดแค่หน้าเว็บกับ API และหน้าตั้งค่าจะบอกว่า "เลขาอีกตัว … ดูแลนาฬิกาและ Discord อยู่"
  - ถ้าตัวแรกหยุด ตัวที่เหลือจะรับงานต่อภายใน 30 วินาที
  - ล็อกนี้กันไม่ให้คำถามใน Discord ได้คำตอบซ้ำสองครั้ง (เคยเกิดจริงวันที่ 5 พ.ย.) และกันไม่ให้แต่ละรอบทำงานซ้ำ
- v1 ที่รันอยู่ตอนนี้ใช้โค้ดที่โหลดไว้ในหน่วยความจำตั้งแต่ 3 พ.ย. ถ้ามันรีสตาร์ท (บูตเครื่องใหม่ หรือล้ม) ไฟล์ service เดิมจะเปิดโค้ดในโฟลเดอร์ ซึ่งตอนนี้เป็น v2 แล้ว แต่ยังเปิดให้ทุกเครือข่าย (`0.0.0.0`) ตาม service เดิม ติดตั้ง v2 เมื่อพร้อม จะได้ใช้ค่าที่ถูกต้อง
